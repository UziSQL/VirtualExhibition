# Ұлы дала — виртуальный музей Казахстана

Работающая учебная выставка ко Дню Республики: центральный атриум с мотивом шанырака, шесть соединённых залов, свободная прогулка и экскурсия. Интерфейс и материалы на русском, отдельные подписи на казахском.

## Запуск

Нужен Node.js 22.12+ (проект проверен с Node.js 24).

```sh
npm ci
npm run dev
```

Откройте адрес, выведенный Vite, обычно **http://localhost:5173**. В Windows PowerShell с запретом `.ps1` используйте `npm.cmd ci` и `npm.cmd run dev`. Для просмотра с телефона используйте сетевой адрес Vite, находясь в одной локальной сети с компьютером.

```sh
npm run typecheck   # TypeScript
npm test            # логика паспорта, вопросов, экскурсии и столкновений
npm run build       # готовый сайт в dist/
npm run preview     # локальный просмотр production-сборки
npx playwright install chromium
npm run test:e2e    # браузерные сценарии; сервер запускается автоматически
```

## Что есть в музее

- **История моей страны**: Декларация 1990 года, независимость 1991 года, лента событий и различие двух праздников.
- **Государственные символы**: флаг в пропорциях 1:2, герб, рассказ о гимне со ссылкой на официальный материал.
- **Культурное наследие**: крупные фотографии музыканта с домброй, казахской юрты и ткачества непосредственно в 3D. Две стилизованные объёмные модели доступны из карточек, домбра также выставлена в витрине.
- **Лица Казахстана**: Абай, Шоқан Уәлиханов и Каныш Сатпаев; настоящие исторические портреты.
- **Моя малая родина**: Шахтинск, музей памяти жертв политических репрессий в Долинке и природа Каркаралинского национального парка; документальные фотографии и проверенные источники.
- **Казахстан будущего**: образование, наука, экология, сохранение памяти и личное пожелание.

В шести залах **17 экспонатов и 6 вопросов**. Экскурсия последовательно показывает все экспонаты, выделяя 21 секунду на остановку; ориентир с переходами — 6–8 минут. Доступны пауза, предыдущая/следующая остановка и завершение. Все шесть залов дают отметку в паспорте.

Паспорт отмечает зал только после открытия содержательного экспоната (в том числе при прибытии к нему в экскурсии). Повторное открытие не дублирует отметку. Неверный ответ можно исправить. Прогресс, правильные ответы и пожелание сохраняются в `localStorage` под ключом `uly-dala-passport-v1`. Сброс требует отдельного подтверждения и удаляет также пожелание. При недоступном хранилище сайт сообщает об этом и продолжает работать в памяти.

## Управление

Компьютер: WASD / стрелки — движение; клик по сцене — включение обзора мышью; Esc — освобождение курсора и меню. Подойдите к экспонату ближе 4,5 м, наведите прицел и нажмите E или кликните. Активный прицел подсвечивается золотым.

Телефон: левый джойстик — движение, отдельная правая область «Обзор» — поворот камеры; кнопка «Открыть» или нажатие на близкий экспонат. Кнопки залов и схема музея доступны на всех устройствах.

Стены, границы здания и постаменты участвуют в столкновениях. Автоматические маршруты ищутся по свободной сетке с проверкой той же геометрии. Во время экскурсии ручное движение отключено. Нативные диалоговые окна блокируют фон, удерживают клавиатурный фокус и закрываются по Esc; после закрытия фокус возвращается к вызвавшему элементу, если он ещё существует.

- Город Шахтинск, Карагандинская область.

Полное название доступно в разделе «Об авторе выставки», краткое — в подвале. Фотографии школы не добавлены: подтверждённого снимка с условиями использования нет.

Региональные тексты и ссылки находятся в `regionalExhibits`, фотографии и их атрибуции — в `src/data/media.ts`. Новому региональному экспонату нужны постоянный `id`, название, подпись, содержательный текст, проверяемый источник фактов и снимок с подтверждённой лицензией. Не заменяйте местные объекты похожими фотографиями из другого города.

## Как менять коллекцию

Названия залов хранятся в `halls` (`src/data/museum.ts`) как `names.kk` и `names.ru`, номер — в `number`. Название центрального атриума находится там же в `atrium`. Все формулировки полные: не сокращайте их отдельно в интерфейсе. `HallTitle.tsx` выводит казахское название сверху и русский перевод размером ⅔ основного текста; его используют навигация, каталог, схема, паспорт и экскурсия. `HallSign.tsx` рисует такие же пары на 3D-табличках, переносит длинные строки и дожидается загрузки локального Noto Serif с расширенной кириллицей. Статьи и названия экспонатов остаются на русском.

`src/data/museum.ts` содержит типы `Hall`, `Exhibit`, `Question`, `Source` и сами данные. Экспонат с уникальным `id` получает `hall`, `title`, `caption`, массив `paragraphs` и список идентификаторов `sources`. Поля изображений: `image`, `imageCaption` (что, где и когда снято), `imageCredit`, `imageKind` (`photo`, `archive`, `illustration`, `symbol`, `timeline`). Поле `model` принимает `dombra` или `yurt`. `motif` используется только при отсутствии изображения; готовая коллекция содержит изображение для каждого экспоната. Вопрос содержит варианты, индекс правильного ответа с нуля и объяснение.

3D-залы рассчитаны на **2–3 настенных экспоната каждый**. Для большего числа карточек расширьте компоновку `Architecture` в `src/components/MuseumScene.tsx`. Обычный каталог автоматически показывает весь массив. После изменения `id` старые отметки соответствующего экспоната перестанут учитываться — используйте постоянные идентификаторы.

Изображения храните в `public/images/`, используйте относительный путь к этой папке. JPEG/WebP до 1200–1600 px по длинной стороне обычно достаточны. Для государственных символов сохраняйте оригинал, пропорции и все элементы; не заменяйте их генеративной картинкой. Ошибка отдельной картинки оставляет текстовую карточку доступной.

Процедурные модели находятся в `src/components/Models.tsx`; обе помечены как стилизованные иллюстрации. Для новой модели расширьте тип `model` и компонент `ModelShowcase`. Для внешних GLB создайте `public/models/`, загрузите через `useGLTF` из drei внутри локальной границы ошибок и `Suspense`, задайте реальные размеры, добавьте столкновения при размещении в проходе и укажите лицензию. Не включайте чужие модели без разрешения.

## Доступность и производительность

Палитра архитектуры задана в `GalleryMaterial.tsx`: молочные стены `#F3F0E9`, нейтральный потолок `#FAFAFA`, каменные колонны и обрамления `#DDD8CE`, серо-бежевый пол с тонкими швами и золото шампанского `#B99A59`. Цвет материала пола `#C4C0B7` компенсирует верхнее освещение, чтобы итоговый оттенок оставался около `#D5D1C8`. Самосвечение архитектурных материалов отключено; общий свет уменьшен, потолок получает отдельный мягкий заполняющий свет снизу. Renderer использует sRGB, Neutral tone mapping и экспозицию 1. Фоны информационных панелей белые, основной текст — `#292B2D`; фотографии и государственные символы сохраняют исходные цвета.

Золото использует металличность 0,45, шероховатость 0,42 и отражения от локально сгенерированного `RoomEnvironment` (PMREM 128 px, без сетевых HDR-файлов). Камень получает деликатную процедурную bump-фактуру без цветных прожилок. `ContactShade.tsx` добавляет статические мягкие контактные тени у стен, колонн и постаментов; они остаются видны при отключении динамических теней на телефоне. Направленная PCF-тень смягчена и рассчитывается один раз для неподвижной архитектуры.

Единственный большой цветовой акцент — торцевая стена `#23474C`. `AtriumBackdrop.tsx` рисует на ней название «Ұлы дала», симметричный золотой орнамент и двуязычные подписи с тем же порядком языков. Юрта остаётся центральным экспонатом; дополнительные случайные декоративные предметы не добавлены.

В `ExhibitPanel.tsx` размер рамы следует пропорциям фотографии. Снимок занимает около 65–80% стенда; заголовок и короткая подпись входят в ту же текстуру. Текстуры отмечены как sRGB; у фотоматериала отключены tone mapping и туман, поэтому экспозиция архитектурного света не выбеливает снимки. Фотоплоскость выступает перед рамой на 8 мм, предотвращая пересечение поверхностей. После загрузки изображения canvas перерисовывается, текстура обновляется и запрашивается новый кадр после её назначения материалу. Есть освобождение GPU-текстур и ограниченная анизотропная фильтрация. Атрибут `data-panel-images` на canvas записывает результат после рендера каждой панели для браузерной диагностики; посетителю он не отображается.

До загрузки стенд показывает сообщение об ожидании. Ошибка или таймаут 15 секунд заменяют его понятным сообщением и кнопкой «Повторить загрузку изображений» в интерфейсе. Повтор доступен также из каталога и карточки; описание экспоната остаётся доступным. Повторный запрос обходит кеш неудачной загрузки. При проверке перед изменением оформления пустые стенды не воспроизвелись: все 17 изображений успешно загрузились.

Сцена и просмотр моделей загружаются отдельными модулями. Изображения не зависят от внешнего CDN; шрифты тоже локальные. При неподвижном стартовом экране, паузе экскурсии и открытых карточках используется рендеринг по требованию. Pixel ratio ограничен до 1,5, в низком качестве — 1. Тени выборочные; в низком качестве отключены. В «Авто» узкий экран получает низкое качество.

`prefers-reduced-motion` отключает CSS-анимации и делает переходы мгновенными. При недоступности WebGL2, ошибке сцены или потере контекста предлагаются каталог и повтор загрузки. Каталог можно открыть и при работающем 3D. Фиксированные показатели FPS не заявляются: их нужно измерять на целевых устройствах.

## Публикация

GitHub Pages настроен в `.github/workflows/pages.yml`. После включения **Settings → Pages → Source → GitHub Actions** публикация запускается при каждом push в `main` и вручную через **Actions → Deploy museum to GitHub Pages → Run workflow**. Workflow использует Node.js 24, выполняет `npm ci`, проверку TypeScript, unit-тесты и сборку, затем публикует только `dist/`.

Адрес сайта после успешного развёртывания: **https://uzisql.github.io/VirtualExhibition/**. Сборка получает `--base=/VirtualExhibition/` (имя берётся из репозитория), поэтому модули, шрифты и изображения загружаются из подпапки сайта. Локальный запуск сохраняет прежний адрес. GitHub Pages для приватного репозитория требует подходящего платного тарифа; на GitHub Free репозиторий должен быть публичным.

Проверка такой сборки локально:

```sh
npm run build -- --base=/VirtualExhibition/
npm run preview -- --base=/VirtualExhibition/
# http://localhost:4173/VirtualExhibition/
```

Для другого статического хостинга выполните `npm ci`, `npm run typecheck`, `npm test`, `npm run build` и опубликуйте `dist/` по HTTPS. Сервер приложения и база данных не нужны. Для Netlify / Vercel: build command `npm run build`, output directory `dist`. После публикации проверьте все фотографии, казахские буквы, управление и сведения об авторе на компьютере и телефоне.

## Проверки и визуальный осмотр

Проверки охватывают TypeScript, production-сборку, 16 unit-проверок и браузерные сценарии. Визуальный осмотр включает все шесть залов и страницы автора на компьютере и мобильном экране. Проверяется загрузка всех 17 изображений на 3D-стендах и отсутствие горизонтального переполнения на ширинах 390 и 320 px.

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
node scripts/review-museum.mjs
node scripts/review-room-names.mjs
```

Unit-проверки охватывают паспорт всех шести залов, восстановление данных, вопросы, экскурсию, столкновения и маршруты. Браузерные сценарии проверяют прогулку и захват мыши, открытие по E, модальные окна, весь маршрут из 17 остановок, пожелания, модели, мобильное управление, загрузку каждого изображения именно на 3D-стенде, подписи автора и лицензии. Предусмотрены отдельные проверки недоступной фотографии и резервного каталога без WebGL.

`review-museum.mjs` сохраняет атриум, все шесть залов, автора на компьютере и телефоне, коллекцию и отчёт об ошибках в `artifacts/review/` (не включается в Git). Переменная `REVIEW_OUT` меняет папку результатов, `REVIEW_URL` — адрес сайта (по умолчанию `http://127.0.0.1:5173/`; для Pages укажите полный адрес с `/VirtualExhibition/`). Скриншоты нужно просмотреть вручную; скрипт сам по себе не подтверждает визуальное качество. Браузер — headless Chromium с программным WebGL (SwiftShader). Мобильный экран и указатели эмулируются; проверка на физическом телефоне и измерение FPS на целевых устройствах не проводились.

`review-room-names.mjs` проходит через каждый вход и снимает двуязычную 3D-табличку с расстояния около 3,5 м. Атриум, каталог, мобильная навигация и схема музея на ширинах 390 и 320 px сохраняются в `artifacts/room-names/`. Браузерный сценарий `room-names.spec.ts` проверяет порядок языков, соотношение шрифтов, единственный номер в заголовке и переносы без горизонтального переполнения.
